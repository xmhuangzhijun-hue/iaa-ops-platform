Agent 自动化测试使用可控的模型替身检查权限和副作用，不能当作真实模型理解验证。关键覆盖：本人 / 跨用户 / 跨租户历史隔离、空授权范围、字段权限、撤权和映射变化、只读执行拒绝、参数及金额校验、过期和版本冲突、重复提交 / 批准、批量事务回滚、故障终态和引用编号校验。

独立审查发现的审批竞态先取得失败证据：持有运行锁 → 发起批准 → 撤角色 / 缩范围 → 释放锁，旧实现仍返回 200。修复后先锁运行，再锁定 / 重读用户及映射；3 种等待期撤权全部拒绝，2 种执行中撤权等待配置和回执提交后生效。关键词在 aggregate / daily / raw 三个视图按原报表规则过滤，101 字符拒绝。

种子重置兼容性也取得修改前 2 个外键失败、修后 2 个通过的证据。已有 Agent 计划或运行时，原事实种子现在明确拒绝重置并指向新库；只读事务实测仅执行两次 SELECT，51,840 行事实、36 条计划及运行 / 提案 / 回执数量均未改变。旧 Python 迁移库缺少 Agent 表仍可初始化。

## 人工语义复核：有失败，保留证据

最终查询的表格、5 个账户合计 191,637.88、ROI 极值、两个低于 1 的账户及其消耗占比 50.0%均与来源一致。优先排查 `vivo-demo-005`、再看 `huawei-demo-003` 以及补查日趋势是合理的调查建议。

但正文仍误称 `huawei-demo-003` 消耗最高，实际最高是 `huawei-demo-011` 的 58,068.25；还误称前者绝对负回收差额最大，已有精确收益证据显示 `vivo-demo-005` 差额 −6,873.16，比前者 −5,711.45 更低。声称“量能没问题、更可能是收益端或转化质量”也没有足够依据，CVR 接近不能排除获客成本差异。

因此 **真实工具调用和操作闭环通过，分析语义没有全部通过**。一次比较提示修正未消除错误，本轮停止继续叠提示词，不隐藏失败。界面让使用者回看来源，执行前审阅确定的修改差异；模型没有直接写入通道。后续质量工作应使用固定来源的事实 / 排序评测集、人工评分和模型对照，再决定是否增加审阅步骤，不能靠证据编号存在宣称事实正确。

- 自然语言要求查询 `xiaomi-demo-004` 并准备计划调整，真实运行得到指标、计划、报表和提案 4 个工具事件。来源抽屉日期 2026-09-11 至 2026-09-17，账户查询 1 行；消耗 27,063.91、收益 32,919.44 与回答表格一致。

- 第二次提案 3001 → 3002 点击拒绝，任务显示已拒绝；计划仍为 3001 / 版本 2，该任务没有执行回执。
- 390px 窄屏可切换助手 / 数据区；Markdown 表格可横向滚动。成熟渲染库的 SSR 安全样例也检查了不执行 HTML、不加载图片、过滤危险链接。
