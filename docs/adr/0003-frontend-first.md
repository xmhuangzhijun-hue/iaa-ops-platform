# ADR-0003 前端先行、组件库与模块补全

- 状态：历史阶段决策（2026-09-16，维护者确认）；前端原型阶段已结束
- 前置：ADR-0001、ADR-0002

以下记录原型阶段的开发顺序和界面规划。当前默认导航已连接 Java 后端，fetch mock 拦截已停用，原型和占位路由不再开放；当前依赖为 Ant Design 6。规划模块不能据此视为已交付，实际范围见 [README](../../README.md)。后端选型已由 ADR-0004 确定。

## 背景

功能骨架取自作者此前使用的快应用代运营后台。作者当时是运营视角，账号权限只覆盖「增长管理」一层，平台侧的接入、配置、结算与治理模块从未可见。因此模块清单不能只照抄看得见的页面，要按「这类平台必须有什么」补全。

同时确定开发顺序：**先把界面与交互做出来，再由界面倒推后端技术栈与数据库**。项目要开源，技术选型需兼顾招聘面与社区认知度。

## 决策

1. **前端先行，接口在 fetch 层拦截**。mock 放在应用统一的请求封装里按方法与路径匹配，而不是在组件里塞假数组：后端就位后删掉 mocks 目录即可连真接口，页面代码不改。mock handler 同时充当接口草案，是「由界面倒推契约」的产出物。未被 mock 覆盖的路径直接放行到已实现的真实后端。
   - 初版用了 Mock Service Worker，但内嵌浏览器等环境拒绝注册 Service Worker，导致整页白屏；改为 fetch 层拦截后在任何环境都能运行。代价是浏览器开发者工具的网络面板看不到这些请求。
2. **组件库 Ant Design 5，外壳保留自研**。管理后台的表单、弹窗、权限树、穿梭框、批量操作用 Ant Design：国内后台事实标准，招聘常见，开源读者一眼熟悉。毛玻璃外壳、主题系统与看盘页的宽表（AG Grid）保留自研，作为视觉差异点。AntD 的主题令牌由同一套 CSS 变量驱动，深浅色与 12 套预设一并作用于 AntD 组件。
3. **菜单结构移到前端配置**。每个菜单项声明所需权限，前端按当前账号权限裁剪；后端仍对每个接口独立鉴权。菜单是界面结构，不该由后端写死；这样后端替换时导航不受影响。
4. **后端技术栈暂不锁定**。待界面把数据与交互需求压出来后再定。候选：Java + Spring Boot、Node + NestJS、保持 Python + FastAPI；数据库 MySQL 或 PostgreSQL。现有 FastAPI 后端继续服务已实现的看盘与认证接口，作为参照实现。

## 当时规划补全的模块（不代表已实现）

- **媒体接入**：平台凭据与授权状态、采集任务配置与监控、字段映射管理、数据质量告警。
- **变现与预估**：变现平台接入、各媒体收益预估系数配置。
- **投放闭环**：推广配置编辑与配置版本、批量改价与启停、回传策略、转化规则、屏蔽管理、预警规则、报表推送配置。
- **财务结算**：返点折扣、代投成本、赔付与奖励入账、结算单与对账、账户余额与充值。
- **组织与治理**：团队与投手分组、媒体账户分配、四层权限（菜单 / 数据 / 字段 / 操作）、通知中心、操作审计。

## 理由

- 界面先行能把「页面需要什么数据、什么操作」暴露干净，再设计表与接口，避免先建表再迁就页面。
- 管理后台的价值集中在配置与流程，不在图表；这些页面用成熟组件库做，比自研控件快且更容易被读者理解。
- 开源读者与招聘方都以「看得懂、能上手」判断项目，React + TypeScript + Ant Design 的认知成本最低。

## 后果

- 新模块在后端就位前只能算「界面可用」，不得对外宣称功能已上线。
- mock 数据与真实契约存在漂移风险，因此 mock handler 的请求/响应结构一旦确定，即作为后端实现的验收基准。
- 引入 AntD 后包体增大，看盘页与管理页分包加载。
