# ADR-0002 数据、认证与看盘查询

- 状态：已采纳（2026-09-16，第 2 阶段）
- 前置：ADR-0001

## 数据模型

- **事实表只存媒体给的东西**：`ad_facts` 保存日期、小时、媒体、账户、计划与 7 个基础指标。产品、代理、运营不落进事实表，查询时经 `account_mappings` 补齐。
  - 理由：参考看板中映射经常修正，修正要对历史数据立即生效；写进事实表就得回刷全表。
  - 代价：每次查询多一次按主键的左连接，数据量在单租户百万行级时可接受。
- **未映射账户**：左连接后维度为空，界面显示「未映射」，提醒去映射管理补齐。有代理 / 产品 / 运营数据范围的账号看不到未映射数据，避免范围外数据漏出。
- 迁移由 Alembic 手写，测试用 `compare_metadata` 保证迁移与模型一致；约束命名走统一命名约定。

## 认证

- **口令**：argon2id（argon2-cffi 默认参数）。账号不存在时也做一次校验，响应时间不暴露账号是否存在；错误统一返回 `INVALID_CREDENTIALS`。
- **访问令牌**：JWT HS256，15 分钟，只放用户与租户标识；角色与数据范围每次请求从库读取，停用账号或改权限立即生效。
- **刷新令牌**：随机串，库里只存 SHA-256 摘要，7 天。每次刷新都轮换；已轮换的令牌再次出现视为泄露，吊销该账号全部刷新令牌。
- **临时口令**：`must_change_password` 为真时，只能访问当前账号与改密接口，其余返回 `PASSWORD_CHANGE_REQUIRED`。改密后吊销全部刷新令牌。
- **密钥**：`JWT_SIGNING_KEY` 在非本机环境必须注入，缺失即拒绝启动；本机开发未配置时每次启动随机生成，不写文件。
- 未做：登录限流、账号锁定。公开演示部署前补。

## 权限与数据范围

- 接口按权限码鉴权：看盘读 `dashboard.read`；趋势、ROI 异常、原始明细需 `metrics.real`，与导航一致。
- **对外口径**（代理、客户）看不到收益类指标：收益、ROI、点击 ARPU、回收差额。默认列自动去掉；显式请求返回 403。
- 数据范围（代理 / 产品 / 运营）在 SQL 条件中强制，与筛选条件取交集；导出、筛选可选值走同一套条件。

## 看盘查询

- SQL 只做过滤与基础指标求和，派生指标由领域层用汇总值重算。页面、合计、导出、ROI 异常共用这一条路径，不会出现页面和导出口径不一致。
- 按派生指标排序需要先算后排，所以分组结果在应用内排序分页。分组上限 20,000，超出返回 `RESULT_TOO_LARGE`，要求缩小范围。
- 空值排序：不论升降序都排在最后。
- 按小时看趋势跨度不超过 7 天；拆线最多 8 条，其余并入「其他」。
- 导出 CSV 带 UTF-8 BOM，Excel 直接打开中文不乱码；上限 100,000 行。

## 本机开发与演示数据

- `docker compose up -d postgres`：端口只绑定 127.0.0.1，免口令连接，`shared_buffers=64MB`，适配内存紧张的开发机。部署环境另用带口令与密钥管理的配置。
- `python -m app.demo.seed`：固定种子生成虚构数据，含 36 个账户（3 个未映射）、按分时曲线分布的 24 小时明细，以及 5 个覆盖各角色的演示账号。演示口令写在代码里且只对应虚构数据；公开演示部署只开放只读账号。
- 测试建一次性数据库，迁移到最新并写入 14 天数据，结束即删除。
