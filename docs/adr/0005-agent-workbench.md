# ADR-0005：运营 IDE 与受控 Agent

日期：2026-09-18。状态：本轮实现方向；实际验证见 Agent 验收报告。

## 问题

原中台提供多个报表页面，运营人员需要自行查询、比较并转到其他系统执行操作。作品集希望展示 FDE 的端到端设计：把业务意图接入已有系统，明确身份、数据与执行边界，并向使用者交付可核对的结果。

本作品不声称有真实客户。使用虚构数据可以证明工程行为，不能证明真实投放收益或生产采用率。

## 决策

1. 保留原始数据和业务 API，前端默认入口改为运营工作台。表格是人的观察空间，侧栏 Agent 是查询与操作助手。没有把所有页面替换成聊天气泡。
2. 在 Java 模块化单体内增加 `agent` 模块。第一版一个模型、有限工具集合；模型决定语义、参数与步骤，Java 负责授权、数值、事务和状态。暂不引入新的独立 Python 业务服务、通用 Agent 平台或多 Agent 编队。
3. 使用现有 JDK HTTP 客户端和 Jackson 作有限的模型协议适配。业务边界已经在 Java，额外框架当前不足以抵消迁移和版本兼容成本。没有自研模型、语义分类器或工作流 DSL；迁移至 SDK 时保留工具/授权/提案契约。
4. `agent` 通过 `ReportService` 查询事实，复用指标与范围逻辑；不成为第三个直接读写 `ad_facts` 的业务模块，因此本轮不触发 facts 拆分。
5. 出价、预算写入专用沙箱配置。模型只能提议；批准接口绑定服务端持久提案，重新验证主体、范围与配置版本，再以事务写配置和回执。当前没有媒体 API，界面明确“本地模拟执行”。
6. 新增 `agent.execute` 控制沙箱操作，由管理员/公司管理员/运营角色持有。数据范围仍取服务端代理、产品、运营授权的交集；运行和回执还需属于当前用户。角色不能替代行级权限。
7. 模型输出与数据源输入都不具有权限授予能力。无模型配置、无有效身份、无可见范围时明确不可用或拒绝，不降级成隐藏的全权演示用户。

## 后果与演进

- 业务数据、Agent运行和沙箱执行可以在一个事务数据库中审计，但模型调用不能纳入数据库长事务。
- 持久化运行记录不等于持久任务队列。首版中断后记录失败，用户重新发起；不声明跨实例可靠恢复。
- 审批卡本身也是执行边界。任何待批准参数变化都需形成新的提案，旧版本冲突不能静默覆盖。
- 真正接入媒体时，需另外实现凭据托管、API幂等、远端回执回查、部分成功/补偿、限额和权限映射；本地事务无法保证外部平台的原子性。
- 交付以来源、权限、界面和可复演验收说明为主；模型效果与确定性工程测试分开报告。
