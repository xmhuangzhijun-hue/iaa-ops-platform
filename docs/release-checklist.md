## 可复现验证命令

Java（仓库 `backend-java/`；Docker 可用）：

```sh
./gradlew build
```

Windows 使用 `.\gradlew.bat build`。如果需强制重跑而非复用 Gradle 结果，追加 `--rerun-tasks`。

Python（`backend/`；测试使用独立测试库）：

```sh
uv run pytest -q
uv run python scripts/export_openapi.py --check
```

前端（`web/`）：

```sh
pnpm gen:api
git diff --exit-code src/api/schema.d.ts
pnpm exec tsc --noEmit
pnpm build
```

上述 `git diff` 用于确认**已提交的候选版本**能精确再生类型；正在有意更新契约时，应先审阅并提交对应生成文件，再检查。

双后端对照需要 FastAPI 与 Java 连接同一个专用演示库。在 `backend/` 用 `uv run uvicorn app.main:app --host 127.0.0.1 --port 8000` 启动对照服务，然后在仓库根目录运行：

```sh
python tools/parity/check.py
```

Python 仍有 8 个管理操作返回 `501`；Java 的这些操作通过契约检查，不能声称全部能力与 Python 完全等价。F-01 空授权修复是 Java 的安全修正，旧 Python 不作为该输入的正确性判据。

CI 包含后端、Java、前端和同库双后端对照。远端结果见 [Actions](https://github.com/xmhuangzhijun-hue/iaa-ops-platform/actions) 和 [STATUS](STATUS.md)；本机命令或工作流语法检查只提供本机证据。

## 开源发布流程（本次已获维护者授权）

1. 看过候选版本的实际演示，确认功能、范围与已知限制可接受。
2. 检查工作区、生成文件、忽略规则和提交历史，只包含本项目虚构业务数据；本机交接、原始资料、截图、日志和真实凭据不得误入仓库。
3. 检查提交身份，采用维护者认可的 GitHub noreply 邮箱。本次用干净源码快照建立公开首个提交，原本地历史完整保留；不推送原有私有历史或标签。
4. 确认仓库归属、名称、可见性与 MIT 许可后，才创建远端或推送。本机封版不自动授权推送、公开或创建 Release。
5. 获授权推送后执行 GitHub Actions，查看实际作业日志与产物；失败就修复重跑，全部通过后再创建相应 Release；本次为 RC 预发布。只有远端成功回执才可写“GitHub CI 通过”。

## 公网只读 demo 的额外门槛

- 使用独立虚构数据库，只开放只读业务账号；禁用或移除公开种子的管理账号。前端隐藏按钮不能代替服务端权限与入口限制。
- 注入真实部署密钥与数据库凭据，关闭本机 trust 配置；秘密由部署环境提供，不写入仓库。
- 只暴露 Java 业务服务；Python 对照服务不对外开放。前端使用正式构建和受控 HTTPS 入口。
- 验证可信代理和来源 IP 处理。当前应用不信任转发头，代理后的请求默认共享代理 IP；入口应限制登录总请求，后端不得允许绕过入口直连。
- 明确单实例内存锁定重启清零的限制；多实例或需要持久锁定时先补共享原子状态。不要仅靠放大阈值绕过部署问题。
- 验证授权、字段隔离、导出与只读写拒绝，检查日志中没有令牌或凭据。导入后台任务目前没有跨进程恢复能力，公网只读 demo 不开放此写入口。
