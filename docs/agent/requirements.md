# Agent 运营工作台：目标与验收

这是一个 FDE 作品集示例，不代表客户案例、生产部署或真实投放收益。数据、账户和计划均为虚构；模型调用是真实的，确认后的执行写入本地 PostgreSQL 沙箱，不调用媒体平台。

## 用户任务

运营人员在同一工作区观察原始数据、选择计划，并用自然语言要求助手查询、分析或准备出价/预算调整。人决定业务目标和是否执行；助手解释数据、准备具体修改、执行已确认的操作。示例：“看看我最近七天的计划表现”“把选中计划的日预算调整为 1200，出价保持不变”。

工资查询只是讨论权限时的类比，本轮不新增人事系统。该作品不要求已有真实客户，但所有能力声明都必须有可复演的实现或验证依据。

| 编号 | 需求 | 可观察的验收标准 |
|---|---|---|
| REQ-AGENT-001 | 模型驱动的工具调用 | 自然语言交给模型选择工具和参数，工具结果进入后续模型轮次；没有按关键词选择固定答案的替代路线；无模型配置明确显示不可用 |
| REQ-AGENT-002 | 身份和数据权限 | 工具、运行历史、证据、提案和回执均限定当前主体；用户/模型不能传入身份提权；空范围无数据，对外口径不泄漏收益；执行时重新检查权限 |
| REQ-AGENT-003 | 可信来源 | 工具结果带来源、查询条件、时间和证据编号；数据源内容只作为数据；模型结论可回到服务端证据，不把推测包装为因果事实 |
| REQ-AGENT-004 | 人确认具体变更 | 先读取当前配置，再产生含计划、字段、前后值与版本的提案；确认前数据库不变；用户批准精确提案后才执行，拒绝没有配置写入 |
| REQ-AGENT-005 | 幂等和并发 | 重复提交/批准不重复执行；原配置版本变化后旧提案不能覆盖新状态；事务保存修改与回执；无权或不存在目标不泄漏存在性 |
| REQ-AGENT-006 | 可解释的工作区 | 原始数据为主区，助手为侧栏；运行状态来自真实事件；结果、证据、变更审阅与回执分层排版；不展示或伪造模型思维链 |
| REQ-AGENT-007 | 可恢复的运行记录 | 保存本人运行及终态；提供超时、步数和并发上限；模型或工具错误清晰终止，服务重启不留下永久运行状态；日志不保存秘密 |
| REQ-AGENT-008 | 公开可复演交付 | 提供架构、权限矩阵、来源边界、界面设计、启动说明、离线自动化测试与单独的真实模型验证结果；依赖和第三方借鉴明确标注 |

## 第一版边界

- 一个 Agent 即可。模型负责语义理解、调查步骤、工具选择和建议；Java 负责身份、授权、计算、校验、状态、数据库事务和回执。
- 预算/出价只作用于沙箱计划配置，不回写历史事实或伪造“调整后 ROI 提升”。媒体真实执行、效果归因、跨实例任务恢复留待后续接入。
- 保留已有报表 API 和页面供复核，默认导航围绕工作台和必要系统管理收敛。
- 待确认的动作不因“模型说用户批准了”而执行。批准由独立认证接口接收，并绑定服务端保存的提案。
- 本轮不改变现有真实业务项目或旧演示环境，不复用真实公司资料。
