# 体验运营 Agent

这是虚构数据的本地演示。模型是真实调用；出价和预算只改本地沙箱计划。默认从工作台看数据、向右侧助手下达任务、审阅差异，再决定是否执行。

## 模型配置

按仓库 README 从空库启动 PostgreSQL、Java、事实种子、Agent 计划种子和前端。Java 启动前需设置以下环境变量：

| 变量 | 说明 |
|---|---|
| `IAA_AGENT_BASE_URL` | 兼容 Chat Completions 的接口根地址，例如 `https://api.deepseek.com/v1`；运行器追加 `/chat/completions` |
| `IAA_AGENT_MODEL` | 模型标识，本轮实测 `deepseek-chat` |
| `IAA_AGENT_API_KEY` | 从本机秘密管理器向 Java 进程注入；不写进前端、仓库或命令历史 |
| `IAA_ALLOWED_ORIGINS` | 可选，逗号分隔的精确前端 origin；默认 `http://127.0.0.1:5173,http://localhost:5173` |

接口必须支持标准工具调用和工具结果续轮。非本机模型地址只接受 HTTPS，不跟随重定向。运行器对 DeepSeek 关闭 thinking 模式；其他提供方的兼容性仍需单独验证。没有配置模型时，助手明确不可用，数据页仍可用。

环境变量由 Java 启动进程继承，根目录 `.env` 不会自动注入 Java。模型密钥绝不能命名为 `VITE_*`。请求会把用户提问及其授权范围内的工具结果发送给所配置的模型服务；这里只允许使用虚构数据演示。

若改用独立数据库和端口，Java 设置 JDBC `DATABASE_URL`、`DATABASE_USER`、`SERVER_PORT`，Python 种子设置对应 SQLAlchemy `DATABASE_URL`，前端设置 `VITE_API_TARGET`；同时把新前端 origin 加入 `IAA_ALLOWED_ORIGINS`。不要把 Java 和 Python 的连接 URL 混用。

## 五分钟演示

1. 用 `demo.operator` / `iaa-demo-2026` 登录。日期选择最近七天；种子截至生成时的昨天，不含当天数据。默认进入 `/workspace`。
2. 观察原始表，筛选账户或输入关键词，点击查询。对助手说：「按当前筛选复盘账户的消耗和 ROI，给排查建议，先不修改配置。」
3. 等待回答，展开真实工具事件。检查查询日期、筛选条件、来源、记录和数值；引用编号存在不保证每句话都正确，应与原表核对。
4. 切到「计划操作」，选择一条可见计划。输入：「把选中计划的日预算调整为 1200 元，出价保持不变，先给我看修改。」若原预算已经是 1200，请选另一个目标金额。
5. 查看前后值和到期时间。此时计划配置尚未改变。确认则得到实际写入回执；拒绝则任务结束、配置不变。
6. 查看「操作回执」并回到计划表核对金额。再以 `demo.readonly` 登录，同样要求修改；后端不会授予执行能力，不显示别人的历史和回执。

在任务运行时可以离开工作台，稍后从本人运行列表回看；关闭页面不等于取消服务端任务。第一版没有多轮会话记忆：每次发送是独立任务，页面上下文会附上，之前的对话不会隐式加入下一任务。

## 状态与失败

- 一个任务最多 8 个模型轮次、12 次工具调用，并发上限 2。总时间预算 150 秒，单次外部调用最多 45 秒，最长可能等到当前调用结束；页面提示约 3 分钟。
- 提案有效期 30 分钟。计划版本、权限或归属变化后不能继续批准旧提案，应重新准备。
- 服务重启会把未结束运行标为失败，不会后台自动批准或重复执行；尚未实现持久任务队列。
- 运行、证据和回执属于本人；权限 / 归属变化会使旧运行不可访问。当前实现保守地对整租户映射做指纹，其他账户归属变化也可能要求重新运行。
- 真实模型回答具有波动。它能给调查建议，不应把账户之间的相关性直接解释为原因；金额最终以差异和回执为准。

## 可复制的真实模型检查

先完成本机配置和种子，再从仓库根目录执行。脚本只允许 `http://127.0.0.1` 或 `http://localhost`，输出仅有虚构任务结果，不记录令牌 / API key。

```sh
python tools/agent/verify_live.py --scenario query --output .local/query.json
python tools/agent/verify_live.py --scenario proposal --approve --output .local/proposal.json
python tools/agent/verify_live.py --scenario readonly --output .local/readonly.json
```

如使用其他后端端口，加 `--base http://127.0.0.1:18081`。第二条明确批准脚本生成的虚构变更：第一条可见计划的预算增加 100 元，检查确认前不变、批准后金额和版本一致、重复请求返回同一回执。不加 `--approve` 时只生成待确认提案。

这些检查验证工具选择、状态和副作用，不自动证明复盘结论正确，也不构成生产成功率。人工判断和实际结果单独记录在 [验收报告](../../reports/agent-acceptance.md)。
